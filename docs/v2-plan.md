## 지금 상태 진단

기능은 다 있습니다. 문제는 **"내 노트북에서 도는 걸 전제로 만든 부분"**이 그대로
출시 경로를 막고 있다는 것입니다.

| 지금                                            | 출시하면 벌어지는 일                                                                                                 |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `EXPO_PUBLIC_*_API_KEY` 가 번들에 리터럴로 박힘 | APK 에 `strings` 만 돌려도 키가 나옵니다. 며칠 안에 남의 과금으로 쓰입니다                                           |
| ComfyUI 가 팀 노트북 · 사설 IP · GPU 1개 직렬   | 사진 생성이 100% 실패합니다. 한 장에 8분, 그걸 위해 켜둔 `usesCleartextTraffic` 도 심사에서 걸립니다                 |
| 로그인이 "이 기기에 닉네임이 있냐"가 전부       | 앱을 지우거나 폰을 바꾸면 몇 주 키운 캐릭터가 사라집니다. 육성 게임에서 치명적입니다                                 |
| `server/` 가 `node:sqlite` + 인증 없음          | `GET /conversations/:deviceId` 는 ID 만 알면 남의 대화를 내줍니다. `DatabaseSync` 는 동기 API 라 요청이 직렬화됩니다 |
| 앨범이 기기 로컬 (IndexedDB / 파일)             | 기기 이전 불가, 백업 없음                                                                                            |

**살릴 것은 확실합니다.** `game.ts` 의 순수 함수 게임 규칙, SVG 캐릭터 조합
(20종 × 4단계, 에셋 0개), `storage.ts` 가 "나중에 서버가 생기면 이 파일 구현만
바꾸면 되도록" 래핑돼 있는 구조 — 이 세 가지가 v2 에서 값을 합니다.

## 선택 기준

수익이 목표가 아니므로 기준이 달라집니다.

1. **이력서에 쓸 수 있는 학습 신호** — "직접 만들었다"고 말할 가치가 있는 것만 직접 만듭니다
2. **평상시 0원에 가까울 것** — 고정비가 있으면 몇 달 뒤 내려버립니다. 포트폴리오는 **계속 살아 있어야** 값이 있습니다
3. **끝까지 갈 수 있을 것** — 완벽한 아키텍처보다 스토어에 올라간 앱이 낫습니다

여기서 가장 중요한 판단은 **뭘 직접 만들고 뭘 사올지**입니다.

- **사옵니다** — 인증, DB 운영, 파일 스토리지. 직접 만들면 시간은 다 쓰고 배우는 건 적습니다 (직접 만든 JWT 는 아무도 안 좋아합니다)
- **직접 만듭니다** — LLM 오케스트레이션, 이미지 생성 파이프라인, 도메인 스키마 설계, API 계약. 이게 이 프로젝트의 본체이고 남이 대신 못 해줍니다

## 기술 스택 결정

| 영역        | 선택                              | 왜 이것인가                                                                                                                           |
| ----------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| API 서버    | **NestJS + TypeScript**           | 국내 Node 백엔드 채용의 사실상 표준. 모듈 · DI · DTO 검증을 강제해서 "구조를 아는 사람"으로 보입니다. 앱과 TS 통일이라 타입 공유 가능 |
| DB          | **Postgres** (Supabase 또는 Neon) | SQLite 에서 벗어나는 게 핵심. 관리형이라 백업 · 커넥션 풀이 무료로 딸려옵니다                                                         |
| ORM         | **Drizzle**                       | 마이그레이션이 SQL 파일로 남아서 "스키마를 설계했다"가 증명됩니다. Prisma 도 무방하지만 Drizzle 이 SQL 을 더 배우게 합니다            |
| 인증        | **Supabase Auth** (Google 소셜)   | 직접 만들 이유가 0. 토큰 검증 가드 붙이는 경험만 얻고 넘어갑니다                                                                      |
| 스토리지    | **Supabase Storage**              | signed URL 발급 패턴만 익히면 충분. 트래픽이 커지면 Cloudflare R2 (egress 무료)                                                       |
| 이미지 생성 | **Gemini 이미지 모델**            | [아래 절](#사진-생성을-로컬-pc-에서-떼어내기) 참고                                                                                    |
| 호스팅      | **Cloud Run**                     | **scale-to-zero 라 안 쓰면 0원.** Docker 로 배포해서 컨테이너 경험이 남고, Gemini 와 같은 GCP 라 프로젝트가 하나로 정리됩니다         |
| CI/CD       | **GitHub Actions**                | `npm run check` 와 `npm run test:persona` 가 이미 있는데 자동 실행이 안 됩니다. 붙이는 데 반나절                                      |
| 모니터링    | **Sentry** (앱 + 서버)            | 무료 티어로 충분. 없으면 출시 후 눈을 감고 운영합니다                                                                                 |
| 타입 공유   | **pnpm workspace + zod**          | `packages/shared` 에 스키마를 두면 API 계약이 컴파일 타임에 깨집니다. 실무에서 자주 쓰는 패턴                                         |

### 바꿀 수 있는 지점

계획을 통째로 다시 짜지 않고 갈아낄 수 있는 곳들입니다.

| 이걸 바꾸면                     | 계획의 어디가 바뀌나                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| NestJS → **Hono**               | 엔드포인트가 6~7개뿐이라 규모에는 더 맞고 Cloud Run 과 상성도 좋습니다. 대신 "구조 설계" 신호는 약해집니다 |
| NestJS → **Spring Boot**        | 국내 채용 수요는 가장 큽니다. 대신 타입 공유가 사라지고 학습 곡선 때문에 일정이 1.5~2배로 늘어납니다       |
| NestJS → **FastAPI**            | AI 생태계와 가장 가깝습니다. 이미지 · LLM 파이프라인을 깊게 파려면 유리합니다                              |
| Cloud Run → **Fly.io + Docker** | 인프라 · DevOps 를 배우고 싶다면 이쪽. DB 도 직접 컨테이너로 띄우면 배우는 게 많지만 시간이 1.5배 듭니다   |
| Supabase → **직접 구현**        | 인증을 직접 만들면 Step 3 이 2주 늘고, 얻는 학습 신호는 오히려 작습니다. 권하지 않습니다                   |

## 사진 생성을 로컬 PC 에서 떼어내기

두 갈래가 있습니다. `krea2_identity_edit.json` 워크플로를 서버리스 GPU 로 옮기거나,
아예 이미지 API 모델로 갈아타는 것입니다.

|               | ComfyUI → 서버리스 GPU (fal.ai · RunPod)          | **Gemini 이미지 API로 교체 (권장)** |
| ------------- | ------------------------------------------------- | ----------------------------------- |
| 생성 시간     | 수십 초 ~ 수 분                                   | **수 초**                           |
| 필요한 인프라 | 작업 큐 + 워커 + webhook + 푸시 알림              | 요청 / 응답 하나                    |
| 비용          | GPU 초당 과금                                     | 이미지당 소액, 무료 티어 있음       |
| 모델 라이선스 | **직접 확인 필요 — 상업적 이용 불가면 출시 불가** | 약관이 명시돼 있음                  |
| 배우는 것     | GPU 인프라, 큐, Docker                            | LLM 멀티모달 파이프라인             |

**8분이 수 초가 되면 아키텍처가 통째로 단순해집니다.** 큐도 워커도 푸시 알림도
필요 없어지고, `comfy.ts` 의 `TIMEOUT_MS = 30분`, 접수증(`PhotoJob`) 저장,
`photo-job.tsx` 의 폴링이 전부 사라집니다. Cloud Run 의 scale-to-zero 와도
상성이 좋습니다 — 항상 떠 있어야 하는 워커가 없으니까요.

그리고 "나 + 캐릭터가 함께 있는 사진"은 **정체성 보존 + 다중 이미지 합성**인데,
Gemini 의 이미지 편집 모델(Nano Banana 계열)이 정확히 잘하는 작업입니다.
키도 이미 Gemini 를 쓰고 있어서 그대로 재사용됩니다.

> ⚠️ 모델 id 는 세대가 빠르게 바뀝니다. 착수 시점에 공식 문서에서 현재 이미지
> 모델 이름과 입력 형식을 확인하세요.

큐 · 워커를 꼭 배우고 싶다면 **v1 을 Gemini 로 띄운 뒤** fal.ai 트랙을 옵션으로
붙이세요. 화질 · 일관성 비교 실험까지 하면 그게 오히려 더 좋은 얘깃거리가 됩니다.
순서를 바꾸면 v1 이 안 나옵니다.

## 목표 구조

```
앱 (Expo · Android)              API (NestJS · Cloud Run · scale-to-zero)
  │
  ├ 로그인 ────────────────────► Supabase Auth (Google)
  ├ 사진 판정 ─────────────────► POST /analyses ───► Gemini Flash (비전)
  ├ 대화 ──────────────────────► POST /chats ─────► Gemini Flash Lite
  │                                        └──────► 요약 → Postgres
  ├ 사진 만들기 ───────────────► POST /photos ────► Gemini 이미지
  │                                        └──────► Supabase Storage
  └ 캐릭터 상태 동기화 ────────► PUT  /pets ──────► Postgres

키는 전부 Cloud Run 환경변수. 앱 번들에 비밀이 하나도 없습니다.
```

`server/` 는 걷어내는 게 아니라 여기로 흡수됩니다. Express · SQLite 는 버리지만,
`summarize.ts` 의 프롬프트(이름을 정답으로 못박는 방식 — 실측으로 얻은 결과)와
`turns` / `summaries` 도메인 모델, "204 응답 후 요약을 던지는" 비동기 구조는
그대로 이식합니다.

## 코드 이동 지도

이게 실제 작업량의 핵심입니다. **키를 쓰는 로직이 전부 앱에 있어서, 그걸 서버로
옮기는 게 이번 리팩터링의 본체입니다.**

### 서버로 이동 — 키를 만지는 것 전부

```
src/lib/breed-inference/*      판정. 프롬프트 · 검증 · 재시도 전부
src/lib/llm/*                  LLM 클라이언트
src/lib/persona-chat/*         대화 + 요약
src/lib/photo-prompt.ts        사진 프롬프트
src/lib/comfy.ts               → 이미지 생성 호출로 교체
src/constants/breed-prompt.ts  20-breed-prompts/ 와 prompts:build 파이프라인까지 함께
server/src/summarize.ts        프롬프트는 그대로 살려서 이식
```

### 앱에 남음

```
src/lib/game.ts        게임 규칙. 순수 함수라 클라에서 돌고 서버는 상태만 저장
src/lib/persona/*      성격 합성. mix 만 있으면 재생성되는 순수 함수
src/lib/image.ts       플랫폼 차이 흡수 (+ 업로드 전 리사이즈 추가)
src/components/*       SVG 캐릭터 — 손댈 이유 없음
src/lib/storage.ts     ⭐ 로컬 저장 → API 클라이언트 + 오프라인 캐시로 재작성
```

`storage.ts` 한 파일이 서버 전환을 흡수하므로 **화면 코드는 거의 안 건드립니다.**
v1 에서 "화면은 AsyncStorage 를 직접 부르지 말라"고 규칙을 세워둔 것이 여기서
값을 합니다.

### 게임 규칙을 서버로 안 옮기는 이유

치트 방지가 목적이 아닙니다. 서버 검증을 넣으면 `game.ts` 를 두 곳에서
관리해야 하고, 얻는 건 없습니다. **서버는 상태를 저장할 뿐이고 판정은 클라가
합니다.** 수익이 걸린 앱이라면 다른 판단을 했을 것입니다.

## 단계별 계획

주 10~20시간 기준의 추정입니다. 시간이 절반이면 기간을 두 배로 보세요.

### Step 1 — API 서버 골격 (1~2주)

- NestJS 프로젝트 + pnpm workspace (`apps/api`, `apps/mobile`, `packages/shared`)
- Drizzle 스키마: `users`, `pets`, `analyses`, `conversations`, `messages`, `photos`
- Supabase Auth 토큰 검증 가드, `/health`
- Dockerfile → Cloud Run 배포 → GitHub Actions 연결

**엔드포인트가 0개여도 배포 파이프라인을 먼저 완성하세요.** 나중에 하면 항상
안 합니다.

### Step 2 — 판정을 서버로 (1주)

- `breed-inference` 이식 + `POST /analyses`
- 앱은 사진을 **리사이즈해서** 올립니다 (`expo-image-manipulator`, 장변 1024 정도).
  원본 수 MB 를 그대로 보내는 지금 방식은 비용과 실패율 양쪽에 바로 먹힙니다
- 여기서 `EXPO_PUBLIC_VISION_API_KEY` 가 사라집니다

### Step 3 — 대화와 계정 (1~2주)

- `persona-chat` + `summarize` 이식, Google 로그인
- `storage.ts` 를 API 클라이언트로 교체
- **원문 턴을 지우지 않습니다.** v1 은 요약에 흡수한 뒤 `deleteTurns` 로
  지웠는데(화면이 새로고침하면 빈 대화로 시작하니 맞는 선택이었습니다),
  계정이 생기면 사용자는 스크롤백을 기대합니다. 요약은 "유일한 기억"에서
  **프롬프트 주입용 파생 캐시**로 성격이 바뀝니다
- 요약 호출도 매 턴이 아니라 N턴 또는 토큰 임계값마다. 지금은 메시지 1개당
  LLM 호출이 2회라 비용이 두 배입니다

### Step 4 — 사진 생성 교체 (1주)

- `comfy.ts` → Gemini 이미지. 결과는 Supabase Storage, 목록은 Postgres
- `usesCleartextTraffic` 제거
- 앨범이 서버로 가면서 `album.ts` 의 IndexedDB / 파일 분기도 정리됩니다

### Step 5 — 출시 준비 (1~2주)

- `expo-updates` (긴급 패치용 — 없으면 버그 하나에 스토어 심사를 다시 기다립니다)
- Sentry (앱 + 서버)
- 온보딩 동의 화면 — 얼굴 사진이 외부 LLM 으로 전송되는 것에 대한 제3자 제공 고지
- 개인정보처리방침 (GitHub Pages 로 무료 호스팅)
- **계정 삭제 기능** — Google Play 가 계정 생성 앱에 앱 내 + 웹 양쪽 경로를 요구합니다
- 데이터 세이프티 폼, 저가 안드로이드 실기 테스트 (SVG 80종 조합 + Reanimated 를
  저사양에서 재본 기록이 아직 없습니다)

## 출시 실무 — 일정을 흔드는 것들

### 클로즈드 테스트 기간이 개발 뒤에 붙습니다

**개인 개발자 계정은 바로 프로덕션에 못 올립니다.** 클로즈드 테스트에 실제
테스터를 일정 인원 이상 확보해 일정 기간 유지해야 프로덕션 신청 자격이 생깁니다.
요건이 몇 번 바뀌었으니 콘솔에서 현재 값을 확인하세요 (대략 10여 명 / 2주 규모).

즉 **개발이 끝난 시점부터 최소 2~3주가 더 걸립니다.** 그래서:

- 개발자 계정($25 일회성)을 **Step 1 에서 바로** 결제하고
- **Step 2 쯤에 미완성 빌드로 클로즈드 테스트를 시작**해서 테스터 기간을 개발과 병행시킵니다

팀원 6명이 그대로 테스터가 되면 인원 절반은 채워집니다.

### iOS 는 이번엔 뺍니다

$99/년 고정비 + 심사 난이도가 "경험" 대비 수익률이 낮습니다. Android 로 한 번
끝까지 가본 다음이 훨씬 쉽습니다. 다만 `app.json` 에 `ios.bundleIdentifier` 가
없고 `eas.json` 의 `submit.production` 이 비어 있다는 건 기록해 둡니다.

### 무료 티어가 조용히 잠듭니다

Supabase 무료 프로젝트는 장기 미사용 시 일시정지될 수 있습니다. 포트폴리오는
채용담당자가 **몇 달 뒤에** 열어보는 게 핵심인데 그때 죽어 있으면 의미가 없습니다.
Cloud Scheduler 로 주기적 핑을 걸어두세요.

### 모델 라이선스

Gemini 로 가면 해결되지만, ComfyUI 트랙을 택하면 `krea2_identity_edit.json` 이
쓰는 체크포인트 · LoRA 의 상업적 이용 가능 여부를 **먼저** 확인해야 합니다.
이건 기술 문제가 아니라 출시 가능 / 불가 문제입니다.

## 의식적으로 안 할 것

잘라야 시간이 남습니다.

- **웹 지원** — `Platform.OS !== 'web'` 분기가 `album.ts`, `image.ts`, `dialog.ts` 에 흩어져 있습니다. 타깃이 안드로이드면 웹 분기를 걷어내는 게 코드가 확 줄어듭니다 (README 데모용으로 남길지는 선택)
- **결제 · 광고** — 수익이 목표가 아닙니다. 심사 항목만 늘어납니다
- **게임 규칙 서버 검증** — 위에서 설명한 이유
- **큐 · 워커 · 푸시 알림** — Step 4 를 Gemini 로 가면 필요 없습니다
- **"서버 없어도 앱은 돈다" 분기** — v1 에서는 훌륭한 판단이었지만(팀원이 서버를 안 띄워도 개발 가능), 서버가 필수가 되면 **장애를 조용히 숨기는 코드**가 됩니다. 서버가 죽었는데 사용자에게는 "그냥 기억을 못 하는 앱"으로 보입니다. 명시적 에러 · 재시도로 바꿉니다
