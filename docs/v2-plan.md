## 지금 상태 진단

기능은 다 있습니다. 문제는 **"내 노트북에서 도는 걸 전제로 만든 부분"**이 그대로
출시 경로를 막고 있다는 것입니다.

| 지금                                            | 출시하면 벌어지는 일                                                                                                 |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `EXPO_PUBLIC_*_API_KEY` 가 번들에 리터럴로 박힘 | APK 에 `strings` 만 돌려도 키가 나옵니다. 며칠 안에 남의 과금으로 쓰입니다                                           |
| ComfyUI 가 팀 노트북 · 사설 IP · GPU 1개 직렬   | 사진 생성이 100% 실패합니다. 한 장에 8분, 그걸 위해 켜둔 `usesCleartextTraffic` 도 심사에서 걸립니다                 |
| 로그인이 "이 기기에 닉네임이 있냐"가 전부       | 앱을 지우거나 폰을 바꾸면 몇 주 키운 캐릭터가 사라집니다. 육성 게임에서 치명적입니다                                 |
| `server/` 가 `node:sqlite` + 인증 없음          | `GET /conversations/:deviceId` 는 ID 만 알면 남의 대화를 내줍니다. `DatabaseSync` 는 동기 API 라 요청이 직렬화됩니다 |
| 앨범이 기기 로컬 (IndexedDB / 파일)             | 기기 이전 불가, 백업 없음                                                                                            |

**살릴 것은 확실합니다.** `game.ts` 의 순수 함수 게임 규칙, SVG 캐릭터 조합
(20종 × 4단계, 에셋 0개), `storage.ts` 가 "나중에 서버가 생기면 이 파일 구현만
바꾸면 되도록" 래핑돼 있는 구조 — 이 세 가지가 v2 에서 값을 합니다.

## 이번 v2 의 중심 — AI 파이프라인

학습 목표가 AI 파이프라인이므로 **서버는 "LLM 을 감싸는 껍데기"가 아니라 이
프로젝트의 본체**가 됩니다. 아래 다섯 가지가 v2 의 핵심 산출물입니다.

### 1. 프로바이더 추상화

`vision` / `chat` / `image` 각각에 인터페이스를 두고 구현을 갈아끼울 수 있게
합니다. v1 의 `llm/config.ts` 가 이미 판정과 대화를 갈라둔 이유(요구가 다르다)를
코드 구조로 승격시키는 것입니다.

### 2. 골든셋과 평가 하네스 ⭐

v1 의 `llm/config.ts` 주석에는 이런 실측 기록이 있습니다.

> Qwen3-VL-8B 은 판정은 제대로 했지만 대화에서 "짧게 답한다"와 "마음을 잘
> 드러내지 않는다"를 둘 다 무시했습니다. gemini-3.1-flash-lite 는 같은
> 프롬프트로 전부 지켰습니다.

**이걸 재현 가능한 평가로 승격시키는 게 v2 의 가장 좋은 얘깃거리입니다.**
한 번 손으로 재본 것과, 프롬프트를 고칠 때마다 자동으로 회귀를 잡아주는
하네스는 완전히 다른 물건입니다.

| 무엇을 재나      | 어떻게                                                                             |
| ---------------- | ---------------------------------------------------------------------------------- |
| 판정 정확도      | 얼굴 사진 + 기대 견종 쌍을 30~50개 모아 상위 1·3 적중률. 스키마 검증 실패율도 함께 |
| 대화 지시 준수   | 페르소나별 체크리스트(말수 · 억제 · 말버릇)를 LLM-as-judge 로 채점                 |
| 사진 정체성 보존 | 원본 얼굴과 결과물의 유사도 + 견종 특징 일치 여부                                  |
| 비용 · 지연      | 호출당 토큰과 p50/p95 지연                                                         |

골든셋은 **팀원과 지인 사진으로 직접 만들고 저장소에 올리지 마세요.** 얼굴
사진입니다. 로컬 또는 비공개 스토리지에 두고 경로만 설정으로 받습니다.

### 3. 프롬프트 버전 관리

`20-breed-prompts/*.md` → `prompts:build` → 생성 코드 파이프라인이 이미 있습니다.
좋은 구조라 그대로 Python 으로 옮기고 **버전 태그**를 붙입니다. 모든 LLM 응답에
어떤 프롬프트 버전으로 만들어졌는지 기록하면, 품질이 떨어졌을 때 어느 변경
때문인지 되짚을 수 있습니다.

### 4. 관측성

**Langfuse** 로 모든 LLM 호출을 추적합니다 — 입력 · 출력 · 토큰 · 비용 · 지연 ·
프롬프트 버전. 오픈소스이고 무료 티어가 있습니다. "AI 기능을 만들었다"와
"AI 파이프라인을 운영했다"를 가르는 게 이 부분입니다.

### 5. 구조화 출력 전략

v1 의 `llm/structured.ts` 는 `json_schema` / `json_object` / `prompt` 3단 폴백을
갖고 있습니다. Python 에서는 **Pydantic 모델 하나가 LLM 응답 스키마이자 API
응답 스키마**가 되므로 이게 훨씬 깔끔해집니다. 검증 실패 시 재시도 정책
(몇 번, 어떤 피드백을 붙여서)을 명시적으로 설계합니다.

## 기술 스택

| 영역               | 선택                                 | 왜 이것인가                                                                                                                                  |
| ------------------ | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| API 서버           | **FastAPI**                          | AI 생태계와 가장 가깝습니다. 비동기 기본이라 LLM 호출 대기가 워커를 안 잡습니다. OpenAPI 스키마를 자동 생성해서 앱 타입을 뽑아낼 수 있습니다 |
| 패키지 관리        | **uv**                               | 요즘 파이썬 표준. 설치가 빠르고 `uv.lock` 으로 재현성이 잡힙니다                                                                             |
| 검증 · 스키마      | **Pydantic v2**                      | LLM 구조화 출력 · DB · API 응답 · OpenAPI 를 **한 정의로** 관통합니다. 아래 별도 절 참고                                                     |
| DB                 | **Postgres** (Supabase 또는 Neon)    | SQLite 에서 벗어나는 게 핵심. 관리형이라 백업 · 커넥션 풀이 딸려옵니다                                                                       |
| ORM · 마이그레이션 | **SQLAlchemy 2.0 (async) + Alembic** | 업계 표준. 마이그레이션이 파일로 남아서 "스키마를 설계했다"가 증명됩니다. 드라이버는 `asyncpg`                                               |
| 인증               | **Supabase Auth** (Google 소셜)      | FastAPI 의 `Depends` 로 JWT(JWKS) 검증만 붙입니다. 직접 만들 이유가 0                                                                        |
| 스토리지           | **Supabase Storage**                 | signed URL 발급 패턴만 익히면 충분. 트래픽이 커지면 Cloudflare R2                                                                            |
| LLM SDK            | **google-genai** (공식 Python SDK)   | 판정 · 대화 · 이미지를 한 SDK 로. 프로바이더 추상화 뒤에 둡니다                                                                              |
| LLM 관측성         | **Langfuse**                         | trace · 토큰 · 비용 · 지연 · 프롬프트 버전. 이번 목표의 핵심                                                                                 |
| 품질 · 테스트      | **Ruff · mypy(strict) · pytest**     | Ruff 하나가 lint + format. v1 의 `npm run check` 와 같은 자리                                                                                |
| 호스팅             | **Cloud Run**                        | **scale-to-zero 라 안 쓰면 0원.** Docker 경험이 남고, Gemini 와 같은 GCP 라 프로젝트가 하나로 정리됩니다                                     |
| CI/CD              | **GitHub Actions** (job 2개)         | `node` job: Expo typecheck · lint. `python` job: ruff · mypy · pytest → Cloud Run 배포                                                       |
| 모니터링           | **Sentry** (앱 + 서버)               | Langfuse 는 LLM 만 봅니다. 크래시는 Sentry 가 봅니다                                                                                         |

리포 구조는 **모노레포 툴링 없이** 단순하게 갑니다. 혼자 하니까 도구 설정에 쓸
시간이 없습니다.

```
/            ← 지금 그대로 Expo 앱 (package.json, src/)
/api         ← FastAPI (pyproject.toml, app/, tests/, alembic/)
/shared      ← 견종 정본 데이터 + codegen 스크립트 (아래 참고)
/server      ← 삭제. summarize.ts 프롬프트만 api/ 로 이식한 뒤
```

## Python 을 고른 대가와 이득

정직하게 양쪽을 적어둡니다.

### 대가 — 코드 이동이 아니라 "다시 쓰기"입니다

TypeScript 로 된 `breed-inference/`, `persona-chat/`, `llm/` 을 Python 으로
**재작성**해야 합니다. 테스트도 pytest 로 다시 씁니다. 다행히 이 로직들이
순수 함수 위주라 옮기기 쉬운 편이지만, "복사해서 붙이기"는 아닙니다.
**Step 2~3 에 그만큼 시간을 더 잡아뒀습니다.**

### 대가 — 견종 ID 를 두 언어가 공유해야 합니다

`constants/pet.ts` 의 `BreedId` 를 **양쪽이 다** 필요로 합니다.

- 앱: SVG 캐릭터(`pet-character.tsx`), 성격 프리셋(`persona/presets.ts`), 게임 규칙
- 서버: 판정 프롬프트, 사진 프롬프트(`breed-prompt.ts`)

TS 통일이면 그냥 import 로 끝나는데, 언어가 갈리니 정본을 하나 두고 양쪽으로
생성해야 합니다.

```
shared/breeds.json          ← 정본. 견종 id · 한글명 · 메타
  ├─ codegen → src/constants/pet.generated.ts   (TS union 타입)
  └─ codegen → api/app/breeds.py                (Python StrEnum)
```

`prompts:build` 가 이미 "문서가 원본, 코드는 생성물" 파이프라인이므로 그
방식의 연장입니다. 생성 파일에는 v1 처럼 "직접 고치지 마세요" 헤더를 붙이세요.

### 이득 — Pydantic 하나가 네 곳을 관통합니다

이게 Python 을 고른 진짜 값입니다.

```
Pydantic 모델 하나 (예: BreedMixResult)
  ├─► Gemini 구조화 출력 스키마 (response_schema)
  ├─► 검증 (LLM 이 이상한 걸 뱉으면 여기서 걸림)
  ├─► API 응답 모델
  └─► OpenAPI 스키마 ──► openapi-typescript ──► 앱의 TS 타입
```

**LLM 응답 스키마를 고치면 앱 타입까지 자동으로 따라옵니다.** v1 에서
`validate.ts` 가 손으로 하던 일이 선언 하나로 줄고, 그러면서 앱과의 계약도
같이 맞춰집니다. TS 통일에서 zod 로 얻으려던 것보다 오히려 낫습니다.

## 사진 생성을 로컬 PC 에서 떼어내기

**AI 파이프라인이 학습 목표이므로, 여기를 "빨리 치우는 부분"이 아니라
"두 프로바이더를 비교 평가하는 부분"으로 만듭니다.**

```
ImageProvider (인터페이스)
  ├─ GeminiImageProvider   ← Step 4. v1 출시는 이것으로
  └─ FalComfyProvider      ← Step 5. krea2 워크플로를 fal.ai 로
```

같은 인터페이스 뒤에 두 구현을 놓고 [평가 하네스](#2-골든셋과-평가-하네스-)로
정체성 보존 · 화질 · 지연 · 비용을 재서 고릅니다. **"골라봤다"가 아니라
"재보고 골랐다"가 됩니다.**

|               | Gemini 이미지 API             | ComfyUI → fal.ai                                              |
| ------------- | ----------------------------- | ------------------------------------------------------------- |
| 생성 시간     | **수 초**                     | 수십 초 ~ 수 분                                               |
| 필요한 인프라 | 요청 / 응답 하나              | 작업 큐 + webhook (Cloud Run 타임아웃을 넘김)                 |
| 비용          | 이미지당 소액, 무료 티어 있음 | GPU 초당 과금                                                 |
| 라이선스      | 약관 명시                     | **krea2 체크포인트 · LoRA 상업적 이용 가능 여부를 먼저 확인** |
| 배우는 것     | 멀티모달 프롬프트 설계        | GPU 인프라, 큐, webhook                                       |

### 순서가 중요합니다

**Gemini 로 먼저 출시하고, fal.ai 는 그 다음입니다.**

8분이 수 초가 되면 `comfy.ts` 의 `TIMEOUT_MS = 30분`, 접수증(`PhotoJob`) 저장,
`photo-job.tsx` 폴링이 전부 사라집니다. 큐도 워커도 푸시 알림도 필요 없어지고
Cloud Run 의 scale-to-zero 와도 맞습니다. **먼저 출시되는 앱을 만들고, 그
위에서 실험하세요.** 순서를 바꾸면 v1 이 안 나옵니다.

그리고 "나 + 캐릭터가 함께 있는 사진"은 **정체성 보존 + 다중 이미지 합성**인데,
Gemini 의 이미지 편집 모델(Nano Banana 계열)이 정확히 잘하는 작업입니다.

> ⚠️ 모델 id 는 세대가 빠르게 바뀝니다. 착수 시점에 공식 문서에서 현재 이미지
> 모델 이름과 입력 형식을 확인하세요.

## 목표 구조

```
앱 (Expo · Android)             API (FastAPI · Cloud Run · scale-to-zero)
  │
  ├ 로그인 ───────────────────► Supabase Auth (Google)
  │                              │ JWT
  ├ 사진 판정 ────────────────► POST /analyses ──► VisionProvider ──► Gemini Flash
  ├ 대화 ─────────────────────► POST /chats ────► ChatProvider ────► Gemini Flash Lite
  │                                       └─────► 요약 → Postgres
  ├ 사진 만들기 ──────────────► POST /photos ───► ImageProvider ───► Gemini 이미지
  │                                       └─────► Supabase Storage
  └ 캐릭터 상태 동기화 ───────► PUT  /pets ─────► Postgres (jsonb 한 컬럼)

모든 LLM 호출 ──► Langfuse (trace · 토큰 · 비용 · 프롬프트 버전)
키는 전부 Cloud Run 환경변수. 앱 번들에 비밀이 하나도 없습니다.
```

`server/` 는 삭제하지만 버리는 건 Express · SQLite 뿐입니다. `summarize.ts` 의
프롬프트(이름을 정답으로 못박는 방식 — 실측으로 얻은 결과)와 `turns` /
`summaries` 도메인 모델, "204 응답 후 요약을 백그라운드로 던지는" 구조는
FastAPI 의 `BackgroundTasks` 로 그대로 옮깁니다.

## 코드 이동 지도

**키를 쓰는 로직이 전부 앱에 있어서, 그걸 서버로 옮기는 게 이번 리팩터링의
본체입니다.** 언어가 바뀌므로 "이식"이 아니라 "재작성"입니다.

### 서버로 재작성 (TS → Python)

```
src/lib/breed-inference/*      판정. 프롬프트 · 검증 · 재시도 → Pydantic 으로 단순화
src/lib/llm/*                  LLM 클라이언트 → 프로바이더 추상화로 승격
src/lib/persona-chat/*         대화 + 요약
src/lib/photo-prompt.ts        사진 프롬프트
src/lib/comfy.ts               → ImageProvider 구현체로 교체
src/constants/breed-prompt.ts  20-breed-prompts/ 와 빌드 파이프라인까지 함께
server/src/summarize.ts        프롬프트는 그대로 살려서 이식
```

### 앱에 남음

```
src/lib/game.ts        게임 규칙. 순수 함수라 클라에서 돌고 서버는 상태만 저장
src/lib/persona/*      성격 합성. mix 만 있으면 재생성되는 순수 함수
src/lib/image.ts       플랫폼 차이 흡수 (+ 업로드 전 리사이즈 추가)
src/components/*       SVG 캐릭터 — 손댈 이유 없음
src/lib/storage.ts     ⭐ 로컬 저장 → API 클라이언트 + 오프라인 캐시로 재작성
```

`storage.ts` 한 파일이 서버 전환을 흡수하므로 **화면 코드는 거의 안 건드립니다.**
v1 에서 "화면은 AsyncStorage 를 직접 부르지 말라"고 규칙을 세워둔 것이 여기서
값을 합니다.

### 게임 규칙과 성격 합성을 서버로 안 옮기는 이유

치트 방지가 목적이 아닙니다. 서버 검증을 넣으면 같은 규칙을 두 언어로
관리해야 하고, 얻는 건 없습니다. **서버는 상태를 저장할 뿐이고 판정은 클라가
합니다.** 수익이 걸린 앱이라면 다른 판단을 했을 것입니다.

같은 이유로 `pets` 테이블은 정규화하지 않고 **jsonb 한 컬럼**에 캐릭터 상태를
통째로 넣습니다. 게임 규칙이 앱에만 있으니 서버가 그 안을 들여다볼 일이
없습니다. 스키마 설계 연습은 `analyses` · `messages` · `photos` 쪽에서 충분히
합니다.

## 단계별 계획

주 10~20시간, 혼자 기준입니다.

### Step 0 — 준비 (0.5주)

- **Google Play 개발자 계정 결제**($25 일회성). 이유는 [아래](#클로즈드-테스트-기간이-개발-뒤에-붙습니다)
- GCP 프로젝트, Supabase 프로젝트, Langfuse 계정 생성
- `shared/breeds.json` 정본 추출 + 양방향 codegen 스크립트

### Step 1 — FastAPI 골격 + 배포 파이프라인 (1.5주)

- uv 프로젝트, Ruff · mypy(strict) · pytest 설정
- SQLAlchemy 모델 + Alembic 첫 마이그레이션:
  `users` · `pets` · `analyses` · `conversations` · `messages` · `photos`
- Supabase JWT 검증 `Depends`, `/health`
- Dockerfile → Cloud Run → GitHub Actions 2개 job

**엔드포인트가 0개여도 배포 파이프라인을 먼저 완성하세요.** 나중에 하면 항상
안 합니다.

### Step 2 — 판정 + 평가 하네스 (2주) ⭐

- `breed-inference` 재작성, Pydantic 구조화 출력, `POST /analyses`
- **골든셋 30~50쌍 구축 + `pytest` 로 도는 평가 하네스**
- Langfuse 연결, 프롬프트 버전 태깅
- 앱은 사진을 **리사이즈해서** 올립니다 (`expo-image-manipulator`, 장변 1024
  정도). 원본 수 MB 를 그대로 보내는 지금 방식은 비용과 실패율 양쪽에 먹힙니다
- 여기서 `EXPO_PUBLIC_VISION_API_KEY` 가 사라집니다

이 단계가 v2 의 핵심입니다. 시간이 부족하면 다른 데서 빌리세요.

### Step 3 — 대화 + 계정 (2주)

- `persona-chat` + `summarize` 재작성, `BackgroundTasks` 로 요약
- Google 로그인, `storage.ts` → API 클라이언트
- 대화 지시 준수 평가(LLM-as-judge)를 하네스에 추가
- **원문 턴을 지우지 않습니다.** v1 은 요약에 흡수한 뒤 `deleteTurns` 로
  지웠는데(화면이 새로고침하면 빈 대화로 시작하니 맞는 선택이었습니다),
  계정이 생기면 사용자는 스크롤백을 기대합니다. 요약은 "유일한 기억"에서
  **프롬프트 주입용 파생 캐시**로 성격이 바뀝니다
- 요약도 매 턴이 아니라 N턴 또는 토큰 임계값마다. 지금은 메시지 1개당 LLM
  호출이 2회라 비용이 두 배입니다

### Step 4 — 사진 생성 (1.5주)

- `ImageProvider` 인터페이스 + `GeminiImageProvider`
- 결과는 Supabase Storage, 목록은 Postgres
- `usesCleartextTraffic` 제거, `album.ts` 의 IndexedDB / 파일 분기 정리
- 정체성 보존 평가를 하네스에 추가

### Step 5 — 두 번째 프로바이더와 비교 (1주, 학습 목표용)

- `FalComfyProvider` — krea2 워크플로를 fal.ai 로
- 두 프로바이더를 같은 골든셋으로 비교, 결과를 `docs/` 에 기록
- 이 단계는 **출시를 막지 않습니다.** 일정이 밀리면 출시 후로 미루세요

### Step 6 — 출시 준비 (1.5주)

- `expo-updates` (없으면 버그 하나에 스토어 심사를 다시 기다립니다)
- Sentry (앱 + 서버)
- 온보딩 동의 화면 — 얼굴 사진이 외부 LLM 으로 전송되는 것에 대한 제3자 제공 고지
- 개인정보처리방침 (GitHub Pages 로 무료 호스팅)
- **계정 삭제 기능** — Google Play 가 계정 생성 앱에 앱 내 + 웹 양쪽 경로를 요구합니다
- 데이터 세이프티 폼, 저가 안드로이드 실기 테스트 (SVG 80종 조합 + Reanimated 를
  저사양에서 재본 기록이 아직 없습니다)

### Step 7 — Google Play 제출

---

**합계 약 10~12주 개발**, 여기에 스토어 테스트 기간이 병행됩니다.
Step 5 를 미루면 9~11주입니다.

## 출시 실무 — 일정을 흔드는 것들

### 클로즈드 테스트 기간이 개발 뒤에 붙습니다

**개인 개발자 계정은 바로 프로덕션에 못 올립니다.** 클로즈드 테스트에 실제
테스터를 일정 인원 이상 확보해 일정 기간 유지해야 프로덕션 신청 자격이 생깁니다.
요건이 몇 번 바뀌었으니 콘솔에서 현재 값을 확인하세요 (대략 10여 명 / 2주 규모).

즉 **개발이 끝난 시점부터 최소 2~3주가 더 걸립니다.** 그래서:

- 개발자 계정을 **Step 0 에서 바로** 결제하고
- **Step 3 쯤에 미완성 빌드로 클로즈드 테스트를 시작**해서 테스터 기간을 개발과 병행

v1 팀원 6명이 그대로 테스터가 되면 인원 절반은 채워집니다. 혼자 개발하더라도
테스터는 혼자 못 채웁니다 — 이건 미리 부탁해두세요.

### iOS 는 이번엔 뺍니다

$99/년 고정비 + 심사 난이도가 "경험" 대비 수익률이 낮습니다. Android 로 한 번
끝까지 가본 다음이 훨씬 쉽습니다. 다만 `app.json` 에 `ios.bundleIdentifier` 가
없고 `eas.json` 의 `submit.production` 이 비어 있다는 건 기록해 둡니다.

### 무료 티어가 조용히 잠듭니다

Supabase 무료 프로젝트는 장기 미사용 시 일시정지될 수 있습니다. 포트폴리오는
채용담당자가 **몇 달 뒤에** 열어보는 게 핵심인데 그때 죽어 있으면 의미가 없습니다.
Cloud Scheduler 로 주기적 핑을 걸어두세요.

### Cloud Run 콜드 스타트

scale-to-zero 의 대가입니다. Python 컨테이너가 처음 뜨는 데 몇 초 걸립니다.
비용 0원과 맞바꾸는 것이니 받아들이고, 앱에서 첫 요청에 로딩 표시를 확실히
보여주세요. 정말 거슬리면 min-instance 1 로 올리는 순간 월 고정비가 생깁니다.

### 골든셋에 얼굴 사진이 들어갑니다

**저장소에 커밋하지 마세요.** 로컬 또는 비공개 스토리지에 두고 경로를 설정으로
받습니다. `.gitignore` 에 미리 넣어두세요 — 실수는 한 번이면 충분합니다.

## 의식적으로 안 할 것

혼자 주 10~20시간이면 **자르는 게 계획의 절반**입니다.

| 안 하는 것                   | 이유                                                                                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 웹 지원                      | `album.ts` · `image.ts` · `dialog.ts` 의 플랫폼 분기를 걷어내면 코드가 확 줄어듭니다                                                              |
| iOS                          | 위 참고                                                                                                                                           |
| 모노레포 툴링                | 루트 Expo + `api/` 로 단순하게. 도구 설정에 쓸 시간이 없습니다                                                                                    |
| 인증 직접 구현               | Supabase Auth. 직접 만들면 2주 늘고 학습 신호는 오히려 작습니다                                                                                   |
| 게임 상태 정규화             | `pets` 에 jsonb 한 컬럼                                                                                                                           |
| 큐 · 워커 · 푸시 알림        | Gemini 이미지는 Cloud Run 타임아웃 안에 끝납니다. Step 5 로 fal 을 붙일 때만 필요해집니다                                                         |
| LangChain · LangGraph        | 이 규모엔 오버킬이고, 직접 만드는 쪽이 배우는 게 많습니다. Langfuse 는 관측성이라 별개입니다                                                      |
| 결제 · 광고                  | 수익이 목표가 아닙니다. 심사 항목만 늡니다                                                                                                        |
| "서버 없어도 앱은 돈다" 분기 | v1 에선 훌륭했지만(팀원이 서버를 안 띄워도 개발 가능), 서버가 필수가 되면 **장애를 조용히 숨기는 코드**가 됩니다. 명시적 에러 · 재시도로 바꿉니다 |

## 바꿀 수 있는 지점
